Project: Seychelles National Model United Nations Official Website

Institution: Tyler Nicholas Foundation

Backend: Supabase

Platform: Public Website + Private Management Portal

Session: 2027 — Draft / Unconfirmed

The most important change is that we are removing the Delegate/User Portal completely.

Secured connection

SUPABASE

## 3. The dynamic Annual Sessions system

### Session management controls

Every annual session should support:

- Session name, year, description, theme and official imagery
- Draft, pending approval, confirmed, active, completed, postponed, cancelled or archived status
- Separate public visibility and publication date
- Editable opening and closing dates
- Application opening/closing status and deadlines
- School and delegate capacity settings
- Committee and agenda management
- Country allocation records
- Event and Academy schedule connections
- Session-specific announcements and documents
- Awards, adopted resolutions and results
- Photography, media releases and reports
- Duplicate previous session to create the next year

The public-facing URL could remain `/sessions/2027/`, but while the session is unconfirmed it should not be accessible to ordinary visitors.

This creates an important distinction:

Operational status describes where the programme stands internally. Publication status determines what the public can see. An internal session might be marked Under Planning while its public visibility remains Hidden.

Supabase supports granular database access through Row Level Security, and Storage permissions can likewise be managed through policies. Those protections must be configured carefully; using Supabase alone does not automatically make confidential records safe.&#x20;

## 7. Confidential records and administration

Because we will store both public content and confidential institutional records, the platform should separate them at the database and storage authorization layers.

Public content

Published pages, approved school profiles, news articles, public event details, announcements and downloadable public resources.

Restricted administrative content

Draft documents, institutional correspondence, internal plans, unconfirmed session information, partner discussions and confidential minutes.

Sensitive personal information

Delegate applications, contact information, dates of birth, safeguarding-related records, selection assessments and supporting documentation.

Security requirements include staff-only authentication, mandatory multifactor authentication, granular permissions, private storage with expiring access links, audit trails, controlled exports, secure backups, retention and deletion procedures, and tests that confirm public visitors cannot access draft or confidential data.

The three existing setup roles remain Chairperson, Deputy Chairperson and Secretary. The portal should implement permission settings for these existing positions, with any TNF oversight access granted through an approved arrangement—not automatically assume everyone has unrestricted access.

## 8. Publishing and approvals

No unconfirmed information should appear publicly simply because it exists in Supabase.

The content publishing workflow should be:

Draft

Create and edit privately

Internal Review

Check details and accuracy

Approval

Authorized decision to publish

Scheduled / Published

Public visibility activated

Archived

Retained or withdrawn according to policy

The system should save revisions, allow previewing unpublished pages, record the author and approver, and support rollback to a previously published version.

For example, administrators can fully prepare the Inaugural Session 2027 page today, leave it in Draft, and later make it visible through a controlled approval and publication action.

## 9. Forms and operational data

The existing six Google Forms should be supported from the outset, without requiring us to recreate them immediately.

The Management Portal should allow staff to manage each form's purpose, public-facing label, URL, linked page, opening and closing status, instructions and administrative owner.

If Google Forms responses are to be available inside the portal, that must be implemented as a separate authenticated integration or authorized import process. Merely inserting a Google Form into a website does not securely synchronize its submissions into Supabase.

Later, SNMUN can replace selected forms with native website forms backed by Supabase, maintaining the same administrative workflow without introducing delegate accounts.

## 11. Project acceptance requirements

The entire project should be judged against practical tests, including whether an authorized staff member can:

- Create and publish a new page without a developer.
- Change the homepage design and reorder sections.
- Change navigation labels, dropdowns and links.
- Create an announcement and set its expiry time.
- Create a 2027 session privately, then publish it only after approval.
- Add a future annual session without changing source code.
- Upload, organize and replace public and confidential files.
- Publish news, events, press releases and photo galleries.
- Manage school, delegation and application records securely.
- Change official website content, footer, contact details and social links.
- Review activity history and restore a previous page version.
- Export authorized operational reports.
- Confirm that unauthenticated visitors cannot access private records.
- Recover from an accidental content deletion or failed deployment.

One engineering limitation should be explicit: Almost all day-to-day content and operational administration should be possible within the portal. Fundamental changes to application code, security policy logic, integrations, or underlying infrastructure will still require controlled technical changes and deployment. Giving the CMS unrestricted power to execute arbitrary code or alter database security would create unnecessary risks.

## 12. Non-negotiable project decisions

No delegate or public user accounts

One comprehensive private Management Portal

Supabase as the centralized backend

All standard website content controlled in the dashboard

Dynamic, reusable annual sessions

Unconfirmed content remains private

Strict protection of confidential programme data

This is the architecture I recommend adopting for SNMUN. It is substantial enough to support the entire national programme over multiple years, while allowing the administrative team to operate the website independently after development.

The next technical deliverable should be the Management Portal Specification: an exact screen-by-screen plan of the admin dashboard, including every menu, editor, control, database field, user permission, and publishing workflow. That should be finalized before building the Supabase database and website components.
